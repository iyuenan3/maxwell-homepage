## 目标
做一个**可交互的个人品牌主页 + AI 工程能力的活样本**：让访客（招聘方 / 同行 / 潜在合作者）在 5 分钟内对 Maxwell「这个 AI 产品经理、FDE 与 AI Native 全栈实践者能交付什么」形成具体、可信的印象，用作品和可对话化身代替简历套话。

定位：**个人品牌 + AI 化身**。求职是隐含价值主张（主页确实服务于让人认识 Maxwell 的能力），但**具体求职活动 / 面试材料 / 谈薪不是本产品的内容**（明确排除，归 worklog；与 chat-api 4 层隐私防御一致，见 CORE / RELATIONS）。

## 用户问题
- 招聘方 / 合作者搜到 Maxwell，想快速判断"是不是真的能做 AI 产品落地 / FDE / AI Native 全栈"，但简历是静态套话、GitHub 散落、无统一入口。
- 访客想问具体问题（背景 / 某个项目怎么做的 / 技术栈 / 经历），没有谁能即时回答。
- 终端体 + 可对话化身把"展示能力"和"被提问"合一：化身本身（RAG + 隐私工程 + SSE 流式）就是能力证据。

## 成功指标
- **定性优先**（个人项目，无正式 KPI）：访客留下专业、"这人是真 builder"的印象；化身回答准确、不翻车（不泄求职或雇主机密 / 不伪造第三方产品归属 / 不编造骑行与身体数据）。
- **可观测代理指标**：chat 日志里的对话深度（`msg_count ≥ 5` 的深度对话数）、回访、被 prefilter 拦截的比例（按 IP JSONL 日志，SSH/jq 查，见 CONVENTIONS）。
- **体验优先于成本**：当前阶段明确"先不省 token，先给访客最好体验"（max_tokens 2000 / topK 12 / 召回宁宽勿窄）。
- 暂无设定数值目标 —— 若未来要量化，可从 chat 日志的深度对话率 / 邮件转化起。

## UX 哲学
- **终端隐喻不可替换**（HANDOFF 设计边界）：bash 终端壳 + CRT 扫描线 + 朱砂方印 + 等宽/衬线中文字体；命令式交互（`ls projects/` / `cat README.md` / `git log`）。
- **作品即证据**：项目用 `ls -lah` 列出 + `cat` 详情页，强调"做什么 + 1 个亮点"，不堆术语。
- **第一人称化身但不假装本人**：化身明确是"AI 版 Maxwell"，被质疑身份时坦白；自然、简洁、中文为主。
- **文案不润色**：HANDOFF 文案经 Maxwell 多次定型，禁"优化"；V1 section 注释是 V2 /help 文案的唯一真相源。
- **隐私即体验的一部分**：化身坦白边界（"求职这块不方便公开聊，可邮件联系"）比假装无所不知更可信。
